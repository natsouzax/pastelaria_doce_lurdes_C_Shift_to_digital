# Prompt — agente de backend e dados

Trabalha numa branch própria `backend-data`, criada da versão comum que já contém `docs/contrato-mvp.md` e, assim que estiver pronto, `docs/api.md`. Lê o dossier Cliente C, critérios, `docs/requisitos.md`, `docs/modelo-dados.md` e o contrato. Implementa apenas a tua área: Supabase PostgreSQL, migrações, seed, API REST Next.js Route Handlers, autenticação de Gestora/Produção, permissões e regras no servidor. Não alteres silenciosamente o contrato; comunica incompatibilidades ao agente de arquitetura/integração.

O seed deve preservar os 11 produtos e 8 pedidos originais; documenta as datas atribuídas à agenda sem datas completas. Acrescenta fixtures separadas para a demonstração do dia com seis bolos. Cada bolo personalizado é item individual com peso, mensagem e alergias; um item ocupa uma vaga. Pendente não reserva vaga. A atribuição de vaga ao confirmar após o sinal deve resistir a pedidos concorrentes. Itens têm estado próprio e a encomenda só fica Pronta quando todos estiverem prontos. Pagamentos são simulados; 56 € exigem 17 € de sinal e deixam 39 € em falta. Evita qualquer ligação real a pagamentos ou mensagens.

Testa as regras críticas: prazo de 5 dias/48 h, segunda-feira, limite de seis, simultaneidade, estados por item, sinal/saldo e acesso indevido por perfil. Usa os comandos atuais das ferramentas instaladas em vez de presumir sintaxe. Nunca publiques `.env`, chaves, credenciais ou `node_modules`. Podes criar subagentes para migrações/seed e testes, mantendo a integração sob tua responsabilidade. Faz commit/push na branch e relata comandos de validação, limitações e decisões abertas.
